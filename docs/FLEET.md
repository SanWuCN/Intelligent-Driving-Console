# 本机智能驾驶管理平台

## 启动

在本机 `console` 目录运行：

```bash
npm ci
npm run build
npm run fleet
```

打开 http://127.0.0.1:8870/fleet 。本机管理服务仅监听回环地址，车端继续使用原服务 `:8765`。端口被占用时可运行 `npm run fleet -- --port 8871`。

## 使用

1. 在车辆管理中输入名称、IP 和该车控制令牌。IP 不含端口；添加前会连接并验证车端状态接口。令牌在首次写操作时由车端验证。
2. 选择车辆，进入批量任务，分别选择各车数据目录内的地图与 CSV，选择流程终点。
3. 管理端按环境、硬件、Autoware、地图定位、路径、循迹的顺序执行；前三级已就绪时跳过，地图与路径按本次选择重新加载。默认终点为路径配置。
4. 地图加载后进入人工定位队列。在内嵌屏幕中操作 RViz，点击完成后会验证 `/current_pose` 和车端阶段，再自动切换下一辆。
5. 执行至循迹时，每辆车都需单独确认现场安全后才能下发启动命令。关闭定位窗口不取消任务，可以重新打开队列。
6. 取消任务仅阻止后续步骤，不停止车端已经运行的节点；车辆管理和屏幕弹窗提供急停。停止所有 ROS 节点与流程重启仍在单车控制台中操作。

## 批量任务页

- 上方是新建流程：选车、选地图与路径、选终点，然后提交。
- 下方是进行中的任务。每辆车显示一张**真实步骤账本**（`backend/fleet.py` 记录，不是固定文案）：
  - `#`、步骤名、结果（通过 / 已跳过 / 失败 / 执行中 / 已取消）、耗时、`车端阶段 before → after`、车端自己上报的该步说明。
  - 折叠的「原始事件」列出带时间戳和步骤号的调度记录（已下发哪个 action、跳过原因、失败原因）。
- 每辆车的操作按当前状态出现：
  - 待人工定位 → 人工定位；待运行确认 → 确认运行。
  - 进行中 → 放弃等待 / 取消后续（不停止车端节点）。
  - 失败、中断、已取消 → 重试（新建一个只含该车的任务，继承地图、路径、终点和尝试次数；同一条记录只能重试一次）。
  - 已结束但车端还在循迹 → 复位该车（调用车端 `restart_workflow`，会先下发零速再停节点，需二次确认）。
  - 任何状态 → 打开该车的车端控制台。
- 等待人工的车不会占用其他车的执行槽位：每辆车一个线程，真正的动作下发仍由全局锁串行，因此一次只有一辆车收到指令。

## 任务记录页

- 顶部统计：任务总数、车辆任务数、成功数、失败 / 中断数。
- 工具栏：按车辆 / IP / 任务号 / 地图 / 路径搜索，按状态筛选，显示命中条数与平均耗时，导出 CSV（带 UTF-8 BOM，Excel 可直接打开）、导出 JSON、清空记录。
- 记录按日期分组，每组可折叠；每张任务卡保留完整的步骤账本与原始事件。
- 已结束的任务可单条删除；存在进行中车辆时后端会拒绝删除和清空。

## 状态对账与超时

- **自动对账**：车辆在「等待人工定位」时，如果车端自己已经推进到阶段 5 及以上（例如操作员直接在车端控制台完成了定位和路径加载），平台会识别并放行，事件里记为「平台自动对账放行」。这样车端状态和平台记录不会长期脱节。
- **人工定位上限**：系统设置中的 `localization_timeout` 默认 1800 秒，超时后该车任务置为失败并释放车辆，可以重新发起，避免一辆车被永久占住。设为 0 表示不限。
- **网络容错**：状态轮询连续失败 3 次才判定「车辆连接中断」，单次 Wi-Fi 抖动不会让整行任务失败。写操作（下发 action）不重试，避免重复副作用。

## 数据与实现

- React 管理界面位于 `src/fleet`：`FleetApp.tsx`（外壳与四个页面）、`JobCard.tsx`（任务卡与步骤账本）、`fleetModel.ts`（类型、格式化与导出辅助）、`fleet.css`。
- Python 标准库服务 `backend/fleet.py` 负责本地设备注册、状态聚合、任务调度及 HTTP/WebSocket 代理，无需在车辆开放 CORS。
- 管理端调用车端 `/api/state`、`/api/action`、`/api/screen-ticket`、`/api/screen`，车端无需更换接口。车端 WebSocket 屏幕服务和 VNC 必须已配置。
- 每项批量任务最多选择 50 辆车；每车同时只允许一个活动任务。
- 车辆、令牌、设置、步骤记录和任务记录原子保存于 `runtime/fleet.json`，文件权限为 `0600`，被 Git 忽略。令牌属于本机敏感配置，未加密；不会通过状态 API 或记录导出返回浏览器。
- 服务重启将未完成任务标记为中断（未闭合的步骤记为已取消），不自动重发命令；已启动的车端进程不会因本机服务退出而自动停止。中断的任务可在任务记录中重试。
- 每辆车的行记录包含 `steps`（步骤账本）、`events`（原始事件，最多保留 200 条）、`attempts`、`started` / `finished`、`retried`。
- 失败不会自动重试有副作用的命令，可从任务记录重新配置。实车状态由车端上报，管理界面不伪造车辆或遥测。

## 验证

```bash
npm test          # 38 项：控制台 19 项 + 多车平台 19 项
npm run build
```

`tests/test_fleet.py` 覆盖连接验证、IP 去重、凭证隐藏、文件校验、顺序推进、人工定位门控、循迹安全确认、取消、急停、掉线、服务重启恢复，以及步骤账本的耗时与车端说明、已就绪步骤标记跳过、车端自行推进后的自动对账、人工定位超时释放车辆、单次轮询失败容错、重试与尝试次数、记录删除保护、车辆复位保护。真实 RViz 操作、车端 VNC、CAN 和 ROS 数据流需要车辆在线时联调。

浏览器集成测试 `tests/fleet-browser.mjs` 使用 Playwright，自动启动临时模拟服务并在退出时清理，覆盖两车完整流程、步骤账本内容、记录页搜索 / 筛选 / 导出 / 删除、设置持久化及桌面 / 手机布局。它需要 `playwright`，也可以复用本机 Chrome：

```bash
npm install --no-save playwright-core
PLAYWRIGHT_MODULE=playwright-core PLAYWRIGHT_CHANNEL=chrome node tests/fleet-browser.mjs
```
