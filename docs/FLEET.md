# 本机智能驾驶管理平台

## 启动

在本机 `console` 目录运行：

```bash
npm ci
npm run build
npm run fleet
```

打开 http://127.0.0.1:8870/fleet 。本机管理服务仅监听回环地址，车端继续使用原服务 `:8765`。端口被占用时可运行 `npm run fleet -- --port 8871`。

## 使用

1. 在车辆管理中输入名称、IP 和该车控制令牌。IP 不含端口；添加前会连接并验证车端状态接口。令牌在首次写操作时由车端验证。
2. 选择车辆，进入批量任务，分别选择各车数据目录内的地图与 CSV，选择流程终点。
3. 管理端按环境、硬件、Autoware、地图定位、路径、循迹的顺序执行；前三级已就绪时跳过，地图与路径按本次选择重新加载。默认终点为路径配置。
4. 地图加载后进入人工定位队列。在内嵌屏幕中操作 RViz，点击完成后会验证 `/current_pose` 和车端阶段，再自动切换下一辆。
5. 执行至循迹时，每辆车都需单独确认现场安全后才能下发启动命令。关闭定位窗口不取消任务，可以重新打开队列。
6. 取消任务仅阻止后续步骤，不停止车端已经运行的节点；车辆管理和屏幕弹窗提供急停。停止所有 ROS 节点与流程重启仍在单车控制台中操作。

## 数据与实现

- React 管理界面位于 `src/fleet`，沿用校徽、车端视觉风格和原始实训车图片。
- Python 标准库服务 `backend/fleet.py` 负责本地设备注册、状态聚合、任务调度及 HTTP/WebSocket 代理，无需在车辆开放 CORS。
- 管理端调用车端 `/api/state`、`/api/action`、`/api/screen-ticket`、`/api/screen`，车端无需更换接口。车端 WebSocket 屏幕服务和 VNC 必须已配置。
- 每项批量任务最多选择 50 辆车，并行处理 4 辆；等待人工操作的车辆占用执行槽位。每车同时只允许一个活动任务。
- 车辆、令牌、设置、步骤结果和任务记录原子保存于 `runtime/fleet.json`，文件权限为 `0600`，被 Git 忽略。令牌属于本机敏感配置，未加密；不会通过状态 API 或记录导出返回浏览器。
- 服务重启将未完成任务标记为中断，不自动重发命令；已启动的车端进程不会因本机服务退出而自动停止。
- 系统设置中的默认端口仅用于此后新增设备。刷新间隔为车端轮询间隔；页面每两秒读取本机快照。等待人工操作不受单步超时限制。
- 失败不会自动重试有副作用的命令，可从任务记录重新配置。实车状态由车端上报，管理界面不伪造车辆或遥测。

## 验证

```bash
npm test
npm run build
```

`tests/test_fleet.py` 覆盖连接验证、IP 去重、凭证隐藏、文件校验、顺序推进、人工定位门控、循迹安全确认、取消、急停、掉线及服务重启恢复。真实 RViz 操作、车端 VNC、CAN 和 ROS 数据流需要车辆在线时联调。

浏览器集成测试 `tests/fleet-browser.mjs` 使用 Playwright，自动启动临时模拟服务并在退出时清理，覆盖两车完整流程及桌面/手机布局。使用已安装 Playwright 的环境执行 `node tests/fleet-browser.mjs`；可通过 `PLAYWRIGHT_MODULE` 指定包路径，通过 `PLAYWRIGHT_CHANNEL=chrome` 使用本机 Chrome。
